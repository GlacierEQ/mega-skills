01 / architecture

The capability hierarchy

Every layer has a distinct job. Higher layers integrate verified outputs from lower layers; they do not silently copy, blur, or replace them.

Skill

Precise method.

The smallest maintained, independently useful procedure. A Skill owns its trigger, inputs, outputs, method, atomic artifact, and local validation.

Must own

Procedure + local acceptance check.

Must not do

Orchestrate unrelated work or depend on higher-layer mission logic.

Combo Skill

Reusable chain.

An explicit repeated route across multiple Skills. It owns ordering, dependency contracts, handoffs, and the compound artifact created by the chain.

Must own

Composition + boundary contracts.

Must not do

Copy member methods or silently replace the Skills it composes.

Mega Skill

Mission system.

A conditional long-horizon system that selects routes, maintains durable state, enforces phase gates, integrates evidence, and handles recovery.

Must own

Routing + durable state + cross-artifact integration.

Must not do

Invoke unrelated capability or duplicate lower-layer procedures.

02 / snowball rule

Every layer must add new value.

The unit above a Skill carries forward a real, reviewable asset from the unit below it. Capability gets stronger because integration compounds—not because the prompt gets longer.

08 / why mega-skills

From prompt pile to capability graph.

The point is not to make agents sound smarter. The point is to make capability composable, inspectable, recoverable, and increasingly reusable.

Ad-hoc prompt pile

  • Implicit state trapped in the current conversation
  • Duplicated instructions spread across agents and prompts
  • Unclear authority and approval boundaries
  • Weak handoffs that require reconstructing work
  • Success claims without provider-side receipts
  • Context growth mistaken for capability growth

Capability control plane

  • Durable state with exact recovery points
  • Composable contracts across Skills and Combos
  • Bounded work with explicit ownership and tests
  • Verifiable handoffs and reproducible gates
  • Evidence-linked receipts for actual execution
  • Evolution driven by observed outcomes
