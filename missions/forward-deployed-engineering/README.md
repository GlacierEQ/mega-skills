# Forward Deployed Engineering — Primary Career Lane

## Operator decision

**Primary lane:** Forward Deployed Engineering (FDE)

**Public identity:** Forward Deployed AI Architect

**Primary application title:** Forward Deployed Engineer

**Secondary adjacent titles:** Applied AI Engineer, Applied AI Architect, Forward Deployed Software Engineer, Forward Deployed Infrastructure Engineer, Technical Deployment Engineer/Lead, AI Solutions Architect.

Forward Deployed is not treated as a synonym for sales engineering or implementation management. The target role must preserve the core motion:

`DISCOVER REAL WORKFLOW → FRAME OUTCOME → SCOPE → ARCHITECT → BUILD → INTEGRATE → EVALUATE → DEPLOY → DRIVE ADOPTION → OBSERVE → EXTRACT REUSABLE PATTERN → FEED PRODUCT`

## Market definition

The strongest current FDE roles share five properties:

1. **Embedded problem ownership** — work inside real customer or mission environments, not merely advise from outside.
2. **Production coding** — personally build, debug, integrate, or materially modify the system.
3. **End-to-end delivery** — own discovery through production/adoption rather than hand off after a demo.
4. **Field-to-product feedback** — turn deployment-specific learning into reusable product/platform capability.
5. **Outcome accountability** — success is adoption, workflow impact, reliability, or mission value rather than activity volume.

## FDE archetypes

### 1. Frontier-model FDE
Examples: Anthropic, OpenAI, Reflection.

Core work: embed with strategic customers, discover high-value workflows, build agentic/LLM applications, evaluate model behavior, integrate into enterprise systems, drive adoption, and return field signal to Product/Research.

**This is the primary target archetype.**

### 2. Agent-platform FDE
Examples: LiveKit, Cognition, Decagon, Console, Reducto.

Core work: deploy agent platforms into customer engineering/operations, build integrations and reference implementations, debug production agent behavior, improve adoption, and convert one-off patterns into reusable platform primitives.

**This is an excellent target archetype and may offer the fastest route to documented customer-deployment proof.**

### 3. Enterprise/infrastructure FDE
Examples: Sierra Forward Deployed Infrastructure, Stripe Professional Services FDE.

Core work: customer-owned infrastructure, networking/IAM, integrations, security/compliance, production applications, migration, deployment automation, runbooks, incident/support lifecycle.

**Strong fit where AI/agent systems remain central; avoid roles that collapse into generic cloud consulting.**

### 4. Domain/mission FDE
Examples: OpenAI Government, Healthcare, Legal; Palantir-style mission deployments.

Core work: deep domain workflow decomposition, regulated/mission constraints, custom production systems, operator trust, measurable operational value.

**Potential long-term advantage because prior field/quality/inspection experience can become credible operational-domain signal rather than legacy baggage.**

### 5. FDE-adjacent delivery lead
Examples: Technical Deployment Lead, Agent Product Manager, Deployment Strategist.

Core work: scope, sequencing, stakeholder alignment, adoption, ROI, change management, directing FDE execution.

**Not the first target. Preserve as a future progression once customer-delivery evidence is strong.**

## Current evidence position

The two open hard gates are human/customer-field evidence:

- customer discovery and workflow problem decomposition
- customer deployment support, adoption, and lifecycle expansion

This means the highest-value next proof is **not another internal architecture project**. It is a real, bounded engagement where another person or organization brings a workflow/problem, the operator discovers requirements, builds/integrates a solution, supports go-live, observes use, iterates, and preserves an external outcome/adoption receipt.

## Career operating rule

Prefer roles and projects that maximize:

`CUSTOMER PROXIMITY × TECHNICAL OWNERSHIP × PRODUCTION DEPTH × AGENT/AI RELEVANCE × REUSABLE PATTERN EXTRACTION`

Reject title-inflated FDE roles where the engineer does not write meaningful production code, does not own the outcome, or reports primarily against quota/sales activity.

## Portfolio implication

The portfolio should prove the FDE loop, not just architecture:

`messy problem → bounded problem statement → architecture → implementation → integration → evaluation → deployment receipt → user/adoption evidence → reusable pattern`

Existing systems already prove the middle of that chain strongly. The mission now prioritizes acquiring verified evidence for both ends: real discovery and real adoption.
