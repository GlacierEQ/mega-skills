# APEX Web Build System Mega Skill

## Mission

Turn an ambiguous website or web-application request into a credible, accessible, visually coherent, and verifiably shippable web artifact. This Mega Skill coordinates repository intelligence, visual routing, browser implementation, justified full-stack escalation, and regression evidence while preserving a recoverable mission state. It does not claim deployment, production readiness, live integrations, or domain expertise without the corresponding evidence and approval.

## Selection boundary and non-selection

Select this Mega Skill when the mission spans more than one web lifecycle concern: existing-repository inspection, visual design, coded browser delivery, optional product-behavior escalation, and verification. Do **not** select it for a simple copy edit, a standalone illustration, a mobile-only Expo application, or a specialist domain decision that has no web artifact. Route those cases to the smallest applicable Skill or Combo.

## Compounding structure

| Mandatory route | Conditional route | What the Mega layer adds |
|---|---|---|
| `long-horizon-core` | `capability-readiness` when prerequisites, access, assets, or claims are unverified | Mission-wide state, phase gates, and a recoverable handoff across the web lifecycle. |
| `web-build-foundation` | `capability-readiness` before full-stack escalation or advanced visual/integration claims | A single evidence-bearing web build record that reconciles repository, visual, implementation, escalation, and validation artifacts. |

## Route algorithm

1. Start `long-horizon-core` with `MISSION.md`, `ROADMAP.md`, `CONTEXT.md`, `EVIDENCE.md`, and `HANDOFF.md`; define the website outcome, target repository or project, scope boundary, acceptance tests, approval authority, and stop condition.
2. Run `web-build-foundation` in order. Begin with read-only repository context, then choose the visual production route, then implement the browser artifact.
3. Before any advanced capability, external integration, authenticated behavior, data mutation, generated asset claim, or deployment-adjacent action, select `capability-readiness` and record admission, observed prerequisites, claim boundaries, fallback, and approval state.
4. If a real feature requirement cannot be satisfied by the static route, select the full-stack member path and record the exact feature setup, schema/API/test boundary, secret requirements, and user approval. Otherwise record `FULLSTACK_ESCALATION: NOT_REQUIRED`.
5. Run `mega-skills-test-runner` through the foundation Combo after the implementation diff is complete. Treat a failing build, regression, hierarchy, or diff-hygiene check as a blocked gate, not a success.
6. Reconcile all named outputs into `WEB_BUILD_MISSION_RECORD.md`, disclose residual uncertainty, preserve the exact validation receipt, and write the next recoverable action into `HANDOFF.md`.

## Compound artifact

**Final artifact:** `WEB_BUILD_MISSION_RECORD.md`.

It must contain the mission contract, repository revision and source-of-truth map, selected visual route and asset provenance, implementation summary, responsive/accessibility observations, full-stack escalation decision, readiness record when used, validation commands and exit codes, approval state, residual limitations, and exact next action.

## Integration delta

The `long-horizon-core` Combo preserves the mission across phases; `web-build-foundation` provides the ordered web-specific route; and `capability-readiness` blocks unsupported escalation. This Mega layer adds the cross-Combo decision algorithm, mission-wide artifact reconciliation, approval boundary, and recovery state required to carry a web build from uncertain intake to a truthful delivery record. No lower layer independently owns that integrated route.

## Durable state

`MISSION.md`, `ROADMAP.md`, `CONTEXT.md`, `EVIDENCE.md`, and `HANDOFF.md` are the Mega layer source of truth. The final mission artifact is `WEB_BUILD_MISSION_RECORD.md`.

## Approval and safety boundary

This Mega Skill may inspect and author within an explicitly authorized workspace. It must not silently clone private repositories, reveal secrets, create or enable connectors, send external messages, create schedules, modify production data, deploy, publish, or push repository changes without the applicable user authorization and platform route. Visual or product claims must be scoped to observed evidence; no fake testimonials, ratings, telemetry, or customer outcomes may be introduced.

## Recovery rule

On any failed gate, preserve the failing command, artifact path, revision, owner, and next remediation step in `EVIDENCE.md` and `HANDOFF.md`. Resume from the earliest failed handoff after re-reading the current context capsule; never skip a failed prerequisite by presenting the downstream artifact as complete.
