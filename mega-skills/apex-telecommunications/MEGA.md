# APEX Telecommunications

## Mission
Mission-scale telecommunications intelligence and execution coordination across voice calls, SMS, voicemail, SIP, PSTN, WebRTC and future communication transports while preserving provider neutrality, source provenance, Operator authority and upgradeable upstream cores.

## Compounding structure
- Required combos: `long-horizon-core`, `telecommunications-mission-orchestration`
- Conditional combos: `capability-readiness`, `automation-control`, `epistemic-verification-chain`, `polyglot-systems-verification`, `genius-epistemic-engineering`, `voice-evidence-authenticator`

## Execution protocol
1. Recover current mission/source state and create `MISSION.md` + `CONTEXT.md`.
2. Resolve actor/organization/contact through the Relationship OS while retaining native provider IDs.
3. Preflight freshness, authority, idempotency, destination and channel capability.
4. Select a provider by mission fitness, capability, reliability, quality and marginal cost; provider selection never changes truth authority.
5. Execute only through an explicitly authorized adapter/runtime.
6. Read back native provider state; normalize transport/contact/mission/ack dimensions independently.
7. Extract statements, commitments and contradictions with explicit provenance/truth state.
8. Preserve raw transcript/recording/receipt layers; invoke forensic Skills conditionally when evidence becomes material.
9. Project normalized interaction state into APEX continuity, Attio relationships and DOCKETS case execution without replacing native artifacts.
10. Quality-promote: self-check → source verification → manager review → adversarial check if material → accept/repair/redispatch → preserve verified gain.

## Upstream-core law
Pipecat, LiveKit, Fonoster, WhisperX and other upstream systems remain clean, pinned and replaceable. GlacierEQ behavior belongs in contracts, adapters, sidecars, workers and control-plane code. Upstream upgrades trigger compatibility/eval suites rather than manual core archaeology.

## Genius Mastery / Lineage activation
Use `apex-genius-mastery` as a peer Mega root in evolution pipelines. Relevant independent Genius Lineages are activated by role, not copied:
- `automation`: idempotency, retries, saga/rollback, DLQ/recovery;
- `security`: privilege boundaries, input/webhook validation, secret isolation;
- `metadata-depth`: causal timestamps, cryptographic fingerprints, provenance DAG;
- `email`: cross-channel communication continuity and native-message semantics;
- `document-processing`: transcript/text fidelity and derivative processing;
- `law`: conditional evidentiary/legal-route constraints when communications become case material.

## Cognitive firewall
- Mode: `read_only` by default.
- Allowed without external authorization: read repositories, inspect provider capabilities, run local tests/evals, write local run artifacts, emit verification receipts.
- Human/Operator authorization required for: external call/SMS/network send, credential use, deployment, merge, deletion, legal filing, or other external mutation.

## Human control points
- authorize_external_communication
- approve_provider_credentials
- approve_production_release
- escalate_material_contradiction

## Output contract
Produce `TELECOMMUNICATIONS_MISSION_RESULT.md` backed by native provider receipts and machine-readable semantic/evidence artifacts.

## Local validation
Atomic telecom semantic tests, recursive hierarchy validation, generated pyramid check, deep-work pipeline validation, provider contract/eval suites, and production-readiness evidence must pass before production-ready claims.

## Non-goals
- provider lock-in;
- patching upstream cores for GlacierEQ business logic;
- replacing Attio, DOCKETS or provider-native evidence stores;
- equating API completion with mission success;
- autonomous external communications without the active authority contract.
