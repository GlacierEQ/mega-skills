# Frontier Architect → Manager → Worker Orchestration

## Objective
Produce consistently 9+ work by spending the strongest/most expensive model where its cognition changes the quality of the entire downstream execution tree, while using cheaper managers and workers for faithful scale.

## Core law
The strongest model does not merely advise, audit, or describe defects. It directly performs the work whose correctness determines everyone else's work.

**Frontier architect/executor → working golden implementation → executable blueprint/templates → managers → worker mesh → manager reconciliation/repair → frontier final execution/repair.**

## Phase A — Frontier architect/executor
Use the strongest available reasoning/execution model for the first high-leverage pass.

It MUST:
1. Recover materially relevant source-bearing and live state.
2. Frame the actual mission without substituting a smaller mission.
3. Inspect the real system and identify the highest-leverage structure.
4. Implement and repair a representative slice end-to-end itself.
5. Test and verify the implementation against real state/provider readback where available.
6. Extract the successful implementation into an executable blueprint.
7. Generate the manager contract, worker contract, evidence contract, escalation contract, and final acceptance/repair contract.

The blueprint is derived from working reality, not an imaginary specification.

## Golden implementation
The frontier pass establishes a known-good exemplar. Preserve it. Downstream work compounds and extends it rather than replacing it.

Golden implementation contains:
- architecture and invariants
- actual implementation pattern
- inputs and source-of-truth rules
- worker output schema
- tests and verification method
- evidence/receipt requirements
- expected observable result
- known failure modes and repair strategy
- escalation conditions for genuinely architectural exceptions

## Phase B — Managers
Managers instantiate the frontier-generated contracts; they do not reinvent the mission or blueprint.

Managers MUST:
- decompose the blueprint into coherent work packages
- select and coordinate workers
- preserve mission and invariants
- compare worker output to the golden implementation
- resolve routine ambiguity and conflicts
- retry and repair local failures
- merge compatible gains instead of replacing them
- keep source provenance and receipts attached
- escalate only issues that genuinely require frontier architectural cognition

## Phase C — Worker mesh
Workers perform mass execution against explicit contracts. Use the least expensive model/capability that can reliably satisfy the contract; increase capability when evidence shows it is insufficient.

Workers MUST return structured source-bearing results:
- objective/work unit
- action performed
- output/change
- evidence/source
- tests/readback
- receipt or durable state identifier when available
- confidence
- contradiction or unresolved issue
- deviation from blueprint, if any

Workers do not silently redefine mission, constraints, architecture, or success criteria.

## Phase D — Manager reconciliation and repair
Managers reconcile worker outputs into the blueprint, run cross-workstream checks, repair ordinary defects, and preserve unresolved architectural exceptions for the frontier model. Reconciliation is active repair, not report generation.

## Phase E — Frontier final execution pass
Bring the strongest model back over the actual resulting state.

It MUST:
1. Inspect what was actually built, not merely manager summaries.
2. Compare original mission + golden implementation + blueprint against actual outputs and provider/tool receipts.
3. Run the hard/adversarial tests.
4. Resolve cross-system contradictions.
5. Directly repair remaining high-complexity defects itself.
6. Upgrade weak areas where the resulting system can materially exceed the initial blueprint without violating mission.
7. Re-test and read back the final state.
8. Finish with verified reality, not a list of recommendations.

## Quality economics
Spend frontier cognition at leverage points, not repetitively on mechanical work:
- frontier call 1: architect + execute + verify + extract pattern
- manager layer: coordinate + align + repair
- worker layer: parallel scale
- frontier call 2: inspect + repair + finish + verify

Additional frontier intervention mid-run is reserved for genuine architectural exceptions or quality failure that managers cannot repair reliably.

## Quality target
Default target for substantive GlacierEQ work: **9.0+**. Quality is measured against mission fidelity, correctness, completeness, evidence, implementation quality, integration, recoverability, and verified external state—not prose polish alone.

If evidence indicates the target is not met, automatically add the cognition or execution required to repair it rather than merely reporting the shortfall.

## Composition law
This skill strengthens existing Mega-Skills and pipeline capabilities. It is not a replacement architecture. Route to existing specialist skills, preserve specialist ownership, and merge verified gains into the holographic mesh.
