# Hidden Harm — Cross-Domain

## Mission

Catch hidden harms that do not belong exclusively to GitHub, context, connectors, or casebuilding. Apply to job/application work, research, planning, documents, operations, finance-adjacent workflows, product/system design, automation, and other GlacierEQ work.

## Universal protected dimensions

- human-outcome leverage
- Operator intent/strategy/position
- truth fidelity and authority domain
- capability and quality
- optionality
- reversibility
- privacy/sensitivity
- time/deadline value
- downstream dependencies
- completion state
- source provenance

## Universal hidden-harm patterns

1. **Easy-work capture:** the easiest measurable task displaces the most valuable objective.
2. **Minimum-by-default:** “safe/small/simple” silently lowers the requested ambition or quality.
3. **Artifact substitution:** producing a document, report, checklist, or dashboard is mistaken for changing the underlying state.
4. **Metric substitution:** count/score/status becomes the goal instead of the outcome it was meant to represent.
5. **Premature closure:** partial success, submission, PR, draft, send, or acknowledgement is treated as final outcome.
6. **Convenience centralization:** one store/provider becomes universal truth because it is easy to query.
7. **Optionality destruction:** a route is closed before its unique future value is understood.
8. **Irreversible convenience:** destructive action is chosen because reversal/recovery cost was ignored.
9. **Privacy leakage through summarization or projection.**
10. **Verification capture:** proving things consumes the work budget after enough truth already exists to act.
11. **Human-outcome disconnect:** technically impressive work has no direct or necessary causal path to the actual mission.

## Execution

`NAME HUMAN OUTCOME -> RECOVER OPERATOR INTENT -> IDENTIFY CANDIDATE ACTION -> DIFF PRE/POST ACROSS PROTECTED DIMENSIONS -> REJECT OR REDESIGN HARMFUL TRANSITIONS -> EXECUTE STRONGEST COHERENT ROUTE -> VERIFY REAL OUTCOME CHANGE -> PRESERVE CONTINUATION`

A transition is acceptable only if its net effect is stronger for the mission after accounting for hidden losses.

## Escalation to specialist skills

- repository/branch/CI/release/deployment -> `hidden-harm-github`
- memory/context/history/summary/continuity -> `hidden-harm-context`
- plugins/MCP/providers/data movement -> `hidden-harm-connectors`
- legal/evidence/case work -> `hidden-harm-casebuild`

## Success

The system should become harder to accidentally weaken. Hidden-harm removal is demonstrated by preventing or repairing a concrete loss while preserving the strongest useful continuation.
