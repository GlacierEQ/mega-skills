# HOLOGRAPHIC CASE MESH

## Prime invariant

Never translate a holographic mesh into a hierarchy, master tree, canonical case, single source of truth, or privileged-provider architecture.

The mesh is polycentric. Every case/node is an independently reconstructable hologram of the state visible from its own sources, operator observations, institutional records, uncertainties, contradictions, and inferences.

## Growth law — inflate the tree; do not swap the tree

The default evolution operation is **MERGE / EXTEND / COMPOUND**, never wholesale replacement.

A newer pass, version, checkpoint, branch, tree, schema, or projection is a growth delta. It does not automatically become a replacement authority over the state that came before it.

When stronger or newer work appears:

1. preserve the existing branch as `ACTIVE_IN_MESH`;
2. identify what the new work adds, corrects, narrows, contradicts, or strengthens;
3. transcribe/merge those gains into the living mesh with typed provenance-bearing edges;
4. preserve all unique contributions from the older branch, including source spans, facts, events, contradictions, provenance, unresolved dependencies, receipts, and mechanisms;
5. read back the merged target;
6. retire an older derivative branch only after a zero-unique-contribution test proves that nothing unique would be lost.

Required retirement test:

- `unique_sources_remaining == 0`
- `unique_events_remaining == 0`
- `unique_edges_remaining == 0`
- `unique_contradictions_remaining == 0`
- `unique_provenance_remaining == 0`
- `unique_unresolved_dependencies_remaining == 0`
- `unique_receipts_remaining == 0`
- `merged_target_readback_verified == true`
- `preserves_lineage == true`

If any test fails, the branch remains `ACTIVE_IN_MESH` and the required action is `MERGE_CONTINUE`, not replacement.

Retirement is lineage-preserving deactivation of a drained derivative branch. It is never erasure of source-bearing history.

`LATEST` is only a cursor for where to grow next. It is never shorthand for “discard what came before.”

## Truth model

There is no global `TRUTH` object. Store provenance-bound propositions:

`PROPOSITION_ID | NODE_ID | CLAIM | SOURCE_ID | SOURCE_CLASS | OBSERVER/ACTOR | TIME | TRUTH_STATE | CONFIDENCE | CONTRADICTS | CONFIRMS | NARROWS | SUPERSEDES | NOTES`

Multiple propositions about the same event may coexist. Contradiction is data, not corruption to be normalized away.

## Node kernel

Each node carries enough state to reconstruct itself:

- NODE_ID / NODE_TYPE
- scope / boundary
- observations / fact propositions
- actors / events
- allegations / elements
- sources / provenance
- contradictions / inferences
- damages / remedies
- discovery targets / accountability paths
- obligations / deadlines
- provider states
- local truth states
- aliases / version lineage
- integrity receipts
- typed edges
- provider projection pointers

## Edge law

Relationships are typed bidirectional graph edges, not containment. Use relation types such as INCIDENT_RELATION, HANDOFF, COMMUNICATION, ACTOR_RELATION, EVIDENCE_PROVENANCE, PROCEDURAL_RELATION, CAUSATION, CONTRADICTS, CONFIRMS, NARROWS, SUPERSEDES, DERIVED_FROM, MERGED_WITH, SUPERSEDES_ONLY, DUPLICATE_OF, SAME_PHYSICAL_OBJECT, and ALLEGED_SAME_OBJECT.

Every edge preserves source and truth state. No edge silently transfers liability, duty, actor role, allegation, deadline, or truth.

## Provider law

Notion, Mem, Supermemory, Dropbox, Gmail, OneDrive, TeraBox, GitHub, Supabase, and future systems are peer projections. A provider may specialize, but specialization never creates epistemic supremacy.

Replicate stable IDs, provenance pointers, hashes/receipts, local proposition states, obligations, edges, aliases/version lineage, and peer pointers so loss of any one provider does not destroy reconstructability.

## Anti-collapse rules

1. No single source of truth.
2. No canonical-case requirement.
3. No master incident narrative.
4. No forced normalization of divergent records.
5. Shared people, institutions, dates, vehicles, report numbers, or communications do not merge cases.
6. Facts cross nodes only through explicit provenance-bearing edges.
7. Historical mistakes remain preserved and linked by contradiction/supersession edges.
8. Operator corrections create new state and lineage; they do not erase prior representations.
9. Provider-native records control only what that provider actually recorded or did.
10. A higher-authority source can supersede a proposition for a specific question without becoming global authority over the mesh.
11. Newer artifacts extend the mesh; they do not replace older source-bearing state by recency alone.
12. Consolidation is permitted only when zero unique mechanism/state/provenance would be lost and the merged target has been verified by readback.

## NEX example

Treat `CHERRY-NEX-2026-08-14`, `CHERRY-HPD-26-286438`, `CHERRY-JBPHH-POLICE-2026-08-14`, and `INCIDENT-2026-08-14` as peer nodes. Historical merged identities such as `NEX-JBPHH-2026-08-14`, `NEX / JBPHH / HPD`, `CASES/NEX_JBPHH_RETAIL_INCIDENT`, and `CHERRY_NEX_JBPHH_MASTER_CASE` remain source-bearing nodes/aliases. Do not delete or normalize them; connect them with typed edges.

Family/divorce facts must not leak into NEX/JBPHH/HPD without explicit source support. For example, `spouse/sponsor` may be a NEX/JBPHH disclosure proposition; `former-spouse` from a divorce/family node cannot migrate into it absent independent NEX/JBPHH evidence.

## Recovery loop

`DISCOVER PEERS → REHYDRATE LOCAL NODE → RESOLVE PROVENANCE POINTERS → RESTORE EDGES → PRESERVE CONTRADICTIONS → MERGE NEW GAINS → REACQUIRE MISSING BYTES → VERIFY RECONSTRUCTABILITY → CONTINUE GROWTH`

The output is a living mesh, not a flattened answer.
